⏺ The author never defines "Restricted." The task brief, the original README and
  the esolangs notes all use the name without explaining it. So "unrestricted"
  is my interpretation, based on what the original implementation couldn't do.

  What the name tells us
  - The original repo calls the language "META Restricted Zaddy," with no "ACE."
  - The task calls it "META Restricted ACE Zaddy" and asks to "finish
    unrestricting" it.
  - So the target is a version that matches modulo Associativity, Commutativity
    and Equality, with whatever the restrictions were removed.

  What was restricted in the original
  In the original zaddy.zaddy and bf.zaddy, every rule's pattern is one
  constructor applied to plain variables, _, string literals or []:
  pyCompBlock @ py.Compound(H, B) ==> ...
  bfLoop      @ bf.Loop(Exprs)    ==> ...
  That shape means several things:
  - No nesting. You couldn't write bf.Loop([bf.Minus('1')]), so peephole
    optimizations like "[-] means set to zero" couldn't be expressed at all. The
    original bf.zaddy has a Zero constructor, but no rule ever produced it.
  - No repeated variables. A pattern like Add(X, X) couldn't require both sides
    to be equal.
  - No list patterns beyond what the wiki describes. It says Zaddy "supports
    pattern-matching heads and tails of lists" but "does not fully support
    associative operations." You couldn't find a, b in the middle of a sequence.
  - No commutativity. The wiki says you'd need "one rule per commutator."
  - Equality only partly working. There was an e-graph, but rules couldn't take
    advantage of it through non-linear or nested matches.

  What I built
  I read "finish unrestricting" as removing those limits on what a rule's
  pattern can say:
  - patterns nest to any depth;
  - repeated variables must match the same e-class;
  - list patterns can have any number of Xs… splices anywhere;
  - constructors can be declared .comm, .assoc or .ac, and matching respects
    that, including matching part of a larger AC term.

  That is where most of the rubric's "structured local transformations" and
  "ACE-matching" points come from.

  Another possible reading
  "Restricted" might be a nod to RPython ("Restricted Python"), which Zaddy
  compiles to. I don't think the task means that. It asks for a Nix flake, and
  the existing flake builds the RPython output, so dropping RPython would go
  against the brief. I kept RPython as the target.

  If you know what the author meant, I can check the work against that. Some of
  the original's other gaps are still there: there are no numbers (everything is
  strings), and field types are not checked.
